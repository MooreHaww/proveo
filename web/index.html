        What it is

        Let your tests choose the model. Cheapest first.

        Proveo gives a coding task to the cheapest model you have and runs the answer against your tests. If the answer fails, the next model up gets the task. A more expensive model is only called when the cheaper ones could not pass.

        How it works

        1. Verified memory. An exact repeat of a task reuses a stored answer, and that answer is checked against the tests again.
        2. Your local models, in the order you set. For example a Raspberry Pi 5, then a PC with a GPU.
        3. The cloud, last unless you move it. It is only called if every rung before it failed, and only while the monthly budget allows.

        The first answer that passes your tests wins, and no rung after it is called.

        What it works for

        Tasks that have tests, because the tests pick the winner. There are three ways to run one:

        • Benchmark task: pick one from the built-in set. Its tests are already written.
        • Code task: describe a function, name it and write your own checks, as a table or as code.
        • Command line: eco.py runs a benchmark task from a copy of the repository.

        The ladder shows each rung as it runs: passed, failed or skipped, with the reason, the time and the cost.

        Estimated cost avoided is what the cloud would probably have charged for tasks solved locally. The savings projection scales that up. Both are estimates. Only the benchmark result is measured.

        Honest limits

        • The measured numbers come from small benchmark coding tasks, one run each.
        • The Pi's answers vary between runs. A failed answer is caught by the tests and escalated.
        • The code check runs in a subprocess with a time limit. It is not a real sandbox, and the code a model writes runs on this computer.
        • Weak tests let a wrong answer pass.
        • Savings figures are estimates unless marked as measured.

        Your keys and your data

        Keys: in the desktop app they are encrypted on this computer. With the command line server they are held in memory only. A key goes only to the rung that names it, or to the default Meta rung if it is your only Meta key.

        What leaves this computer: Proveo sends your task description only to the model servers you set up, and nothing to anywhere else. Your checks stay here.

        Log and verified memory: both are files on this computer, in %APPDATA%\Proveo\eco for the installed app and in the repository's results folder for the command line. The log records each run: the rungs tried, pass or fail, tokens, time and cost. It does not keep your description, your checks or the answers. Verified memory keeps each passing answer.

        Budget: spend is added up from this app's own cloud calls this calendar month, using the prices set on each rung. It does not see your provider's account. You get a warning from 80% of the limit, and at 100% cloud rungs are skipped. The desktop app and the command line keep separate budgets.
